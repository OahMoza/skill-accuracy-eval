# 确认门与评测资产（S0 · 确认 / 锁定 / 复用）

> 被 `SKILL.md` §3.0 / §3.3 引用。覆盖两条主线：① 确认门细则（不可跳过）；② 评测资产（场景样本集 / 黄金集）的落盘与复用（v1.5）。

## 一、确认门（不可跳过）

生成的是**草稿**，必须经发起方 / 业务方**逐条显式回执确认**后才能作为正式三件套执行：

- **补充资料 ≠ 确认**：发起方声明"补充业务资料"并上传解析后，必须**回到确认门重新逐条确认**，执行方不得自行将草稿视为已锁定；
- 黄金集每一条都要能指回来源（哪份文档 / 哪条规则）；
- 确认动作必须是**显式逐条回执**（可接受 / 需修改 / 待补充），执行方不得代答"确认"；
- 确认结果**书面化**：形成"黄金集确认记录"（每条 × 确认状态 × 确认人 × 确认日期），随报告一起交付；
- 确认不了的条目标 `待确认`：其支撑的通过一并标"待确认"，结论标"草稿级执行结果"，不视为正式通过；
- 缺业务资料的维度（如没有规则文档）→ 场景样本集保留骨架、黄金集标 "待业务方补充"，**不进入执行**。

### 验收门槛声明（可选，随确认门锁定）

发起方可一并声明分维度验收门槛（如"结果正确性 ≥95%"）——验收门槛须经**线下多人讨论**并留**确认记录**（模板 `assets/threshold-approval-template.md`：条目 × 目标值 × 定标依据 × 冻结声明"看结果前签认、失败后不得改口径" × 签认），随三件套一起书面确认，锁后不可改；未声明验收门槛 → 只出分数与证据，不做达标判定。

### 仅契约一致性声明（写死）

无业务黄金集（仅喂技能说明）时，必须在确认门显式声明"本轮仅契约一致性评测"；无业务黄金集的维度**禁止做达标判定**，S6 报告头尾带同一句边界声明。

### 版本字段（随确认门锁定）

业务资料版本 / 黄金集版本 / 运行环境（模型名 + 版本 + 参数摘要）/ 结论有效期；任一版本变更 → 旧结论失效，需重评。

## 二、评测资产：落盘与复用（v1.5）

### 2.1 什么是评测资产

评测资产 = **场景样本集 + 黄金集**（锁定版），是"评测用的尺子"，跨轮次复用：

- **场景样本集**：S0 生成的场景样本集（id / category / subcategory / input / expected_behavior / difficulty），3 大类 19 子类勾选，不含专家确认的标准答案；
- **黄金集**（golden set）：从场景样本集筛出并经专家确认的标准案例（标准输入 / 标准输出或期望行为 / 判断依据 / 专家点评），参与正式打分与回归。

### 2.2 落盘规范（生成模式锁定后必做）

- 锁定后落盘为独立文件：`场景样本集-<版本>.md` + `黄金集-<版本>.md`（即场景样本集 / 黄金集的资产文件），随评测方留存（仓库 `cases/<被测技能>/` 或评测方本地），**不随技能包分发**；
- 文件头写版本字段（业务资料版本 / 黄金集版本 / 锁定日期 / 确认记录位置）；
- **只增不改**：回填升级 / 补用例生成新版本文件，旧版本保留——与"黄金集版本变更 → 旧结论失效"（evaluation-framework §6.5）衔接；
- 资产文件随评测记录一同交付，供复核与回归。

### 2.3 资产查找前置（S0 第一步，三模式）

评测发起时**先查是否已有本被测技能的锁定评测资产**（资产兼容性取决于业务资料与黄金集是否仍适用于本轮，不随被测技能版本机械失效）：

- **复用模式（有资产且覆盖本次评测）**：加载锁定版场景样本集 + 黄金集 → **跳过喂料与生成** → 确认门（复用确认变体，见下）→ S1 → S2 执行 → S3–S6。token 与人工成本大头（读资料 + 生成 + 逐条确认）不再重复，且保证"同场景样本集"（铁律 7 改版对比的前提）；
- **生成模式（无资产）**：走完整 S0 喂料 → 资料自检 → 生成三件套草稿 → 确认门逐条确认 → 锁定 → **落盘为评测资产** → S1–S6。
- **增量模式（可选，资产存在但需补用例）**：加载既有资产 + **只对新增 / 回填用例走确认**（不重审旧用例）→ 升级产出新版本资产（只增不改）→ S1–S6，细则见 §2.5。

### 2.4 复用确认变体（复用 ≠ 免确认）

复用模式仍过确认门，但范围收窄：

- 核对资产版本与来源：确认业务资料版本 / 黄金集版本与本次评测匹配，且资产仍适用于目标被测版本；
- 核对本次用途：改版对比 / 回归 / 验收，用途变化须声明；
- 仅业务资料 / 黄金集变更导致资产不适用时 → **回生成模式**或先走资产升级（回填/补用例）；被测技能版本变化本身不触发资产重建；旧运行结果不得跨版本复用，仍须本轮重新执行与判定。
- 复用确认结果同样书面化（复用确认记录），随报告交付。

### 2.5 资产升级（增量模式）

- **增量模式（可选）**：已有锁定资产但需补用例（覆盖新场景 / 回填升级问题用例）时，加载既有资产，**只对新增 / 回填用例走确认**（不重审旧用例），升级产出新版本资产后继续 S1–S6；旧版本保留（只增不改）。
- 评测中发现问题用例（归因 `skill_behavior`）→ 按回填升级流程（execution-flow.md S 专项）补四要素 → **写入黄金集新版本** → 纳入后续回归；
- 升级即黄金集版本变更，旧结论按版本失效；`judge_bias` / `unknown` 归因的用例不得直接回填。
