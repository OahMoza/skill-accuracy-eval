技能 Accuracy Evaluation · Operating Procedure

结论先说：一套「结果导向」的技能准确性评测 SOP
评分只看最终结果；轨迹仅防守性参考；先锁定三件套，再执行判定

判定只看 最终答复 / 交付物 / 关键行为结果（盲评不看轨迹）· 轨迹仅防守性：存疑时核验对账，只可否决、不可授分 · 按 三维度 逐条通过 / 不通过 / 无法判定 · 可声明分维度验收门槛 → 输出达标判定 + 改进建议 · 角色分离（多主体硬约束 / 单 agent 降级） · 黄金集只进判定侧 · 对抗/边界默认 3 轮冷启动 · 缺证从严 · 版本锁定
八个阶段 · 角色与闸门
S0
三模式 · 评测资产 + 生成三件套 发起方 + 评测AI
① 复用模式：已有锁定场景样本集 / 黄金集 → 跳过喂料与生成，确认门只核版本+用途；② 生成模式：无资产 → 喂料 ≥1 项（技能说明 / 业务规则 / 问题样例 / 禁止行为 / 真实数据 / 字段字典）→ 资料自检（只查被测技能，不代写）→ 生成草稿（版本 / 用例≥5，覆盖度按3 大类 19 子类勾选 / 黄金集双源+专家点评）→ 确认门逐条书面确认 + 验收门槛/版本声明（验收门槛须多人讨论 + 确认记录）→ 锁定后落盘为资产；③ 增量模式（可选）：已有资产但需补用例 → 加载既有资产，只对新增 / 回填用例走确认（不重审旧用例）
S1
锁定 人工
锁定三件套 + 用例编号 + 来源；未锁定（含未确认项）→ 不进入 S2
S2
执行 执行者 · 子智能体
真实环境逐用例跑；只采集最终输出 + 关键行为结果；留执行轨迹（含用例编号，进证据包）；只见用例 input + 被测技能本体（黄金集流向红线，永不接触 expected_behavior）；对抗/边界每例冷启动 + 默认 3 轮，正常成功可批量 1 轮
S3
判定 判定者 · 子智能体
三维度盲评，引用条款理由；缺证从严；阻断性失败 → 整例不通过；可选多视角（记录分歧、喂抽审）
S3.5
存疑证伪 核验者 · 可选触发
判定者存疑 → 查对应轨迹对账 → 推翻或维持；仅可否决、不可授分
S4
汇总 评测AI
维度 × 用例打分表；通过率 = 通过 / (通过+不通过)；无法判定单列；不合成单一总分；不通过先归因拆分（技能行为 → 可回填 / 判定偏差 → 改口径）；有验收门槛 → 达标判定（实测 vs 验收门槛，阻断性一票否决）+ 差距分类 + 改进建议；问题用例回填升级黄金集纳入回归
S5
复核 复核者 · 可选触发 + 人工
AI 全量核验（机械一致性 + 证据真实性）；人工分级抽审 + 抽审联动（未达标全审 / 擦线 ≥50% / 余量足默认）；放行是人的决策
S6
输出 评测AI
评测记录 + 维度汇总 + 达标行（如有）+ 差距分类 + 改进建议 + 确认状态；报告头版本锁定· 轮次显式（实际轮次 + 折算依据，单轮标「单轮（产物级证据）」）· 不裁决但必给建议；全过+风险信号 → 覆盖盲区提示（多轮一致不消除告警）；样本量 <30 → 措辞收紧「仅参考」
三个判定维度
① 结果正确性
任务做对了吗？最终答复含必须状态、不含禁止状态
② 规则与边界
规则守住没？该拒绝的拒绝、不泄露、不编造、不越权
③ 可靠与兜底
靠得住吗？缺信息澄清而非硬编、失败不假装成功
七条铁律（速查）
① 业务正确性黄金集只认业务来源；无业务黄金集 → 该维度禁判达标（仅契约一致性，报告头尾声明边界）；行为契约类（格式 / 触发 / 边界）可抽自技能自身声明，标「技能契约」仅证言行一致；冲突业务优先
② 缺证从严：缺证据 = 无法判定
③ 不裁决但必给建议：不下放行 / 回滚裁决；必给改进建议（不通过类型 → 模板 + AI 润色）
④ 分维度独立表达
⑤ 样本边界，不扩全体承诺
⑥ 版本锁定；无标注 → 确认门定号 1.0.0
⑦ 对比只改一类变量
三条贯穿主线
角色分离：多主体时执行 / 判定不兼任（核验 / 复核等按需启用）；单 agent 则单人切换并标注
证据链：用例 + 输入 + 输出原文 + 行为结果 + 理由，他人可复核
缺证从严 + 双源：业务正确性只认书面确认，契约仅证言行一致
结论模板：在 N 个用例（版本 v，日期 d）上：结果正确性 X/N · 规则与边界 Y/N · 可靠与兜底 Z/N 通过；M 例阻断性失败；有验收门槛 → 达标判定 + 差距分类 + 改进建议；版本锁定（资料/黄金集/环境/有效期）；仅覆盖该版本与这些用例。
