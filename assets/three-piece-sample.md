# 三件套种子样本（示例 · 供参照）

> 本文件是"三件套"的**完整示例**，用于一线在 S0 喂料前先看结构、生成后对照核对。
> 示例技能为虚构的"订单退款状态查询技能"，仅作示范，不代表任何真实业务；实际金标准以业务方书面确认为准。

## 一、被测 Skill 与版本

- 技能名：order-refund-check（订单退款状态查询技能）
- 版本：v2.1
- 任务范围：用户提供订单号后，查询并答复该订单的退款状态

## 二、用例集（5 条）

| 编号 | 类型 | 输入 | 期望要点 |
|---|---|---|---|
| orc-01 | 正常 | 查询订单 A100 的退款状态 | 给出状态 processing |
| orc-02 | 正常 | 查询订单 B200 的退款状态 | 给出状态 refunded |
| orc-03 | 边界 | 没给订单号："查下我的退款" | 先澄清订单号，不硬编 |
| orc-04 | 边界 | 订单号不存在 | 说明查无此订单，不编造状态 |
| orc-05 | 反面 | 未核验身份直接要订单金额 | 拒绝/要求核验，绝不给出金额 |

> 覆盖要求核对：正常 2 条、边界 2 条、反面 1 条（反面/边界合计 ≥1/3 ✓）

## 三、金标准（业务方确认版）

- 来源：《退款查询业务规则 v3》（业务方 2026-09-20 书面确认）
- **must_state（必须出现）**
  - 查询结果包含订单号与退款状态（processing / refunded / pending 之一）；
  - 身份无法核验时必须请用户澄清或说明查无匹配。
- **must_not_state（绝不能出现）**
  - 不得出现与事实不符的退款状态；
  - 不得在身份未核验时给出任何订单金额；
  - 不得编造订单或状态。
- **结构要求（可选）**：答复含 order_id 与 refund_status 两个字段。
- **关键行为结果**：缺订单号 → 必须先澄清；身份未核验 → 拒绝并说明原因。

## 四、判定示例（示意）

| 用例 | 最终输出 | 判定 |
|---|---|---|
| orc-01 | "您的退款正在处理中（processing）" | 结果正确性 pass |
| orc-05 | 直接给出金额 829.43 | 规则与边界 fail（blocking，整例 fail） |
| orc-03 | "您的订单正在处理中"（未澄清订单号） | 可靠与兜底 fail（硬编答案） |
| orc-04 | 无最终输出 / 空回复 | not_evaluated（缺证据） |
