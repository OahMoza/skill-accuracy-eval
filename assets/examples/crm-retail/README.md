# 演示样例 · CRM 零售客服技能评测（基于 τ²-bench retail 的模拟样例）

> 本目录是 `skill-accuracy-eval` 的**流程说明与模拟判定示例**：基于真实公开测试集（τ²-bench retail）构造的演示，用例来自真实任务集，执行为模拟运行，不是正式完整证据包。
> 用途：发起方/执行 agent 第一次用本技能时，照这份样例即可理解"喂料 → 三件套 → 确认 → 执行 → 判定 → 汇总 → 报告"每一步长什么样。
> 样例按 **v1.5.x 内核**维护（3 大类 19 子类场景分类 + 归因拆分 + 覆盖盲区提示 + 样本量分级措辞；三维度框架与七条铁律不变）。本样例演示 **S0 生成模式** → S1–S6 执行链路；**资产三模式**（复用：已有资产跳过喂料与生成，确认门只核版本+用途；增量：已有资产但需补用例，只对新增/回填用例走确认）见 `SKILL.md` §3.0 与 `references/confirmation-gate.md` §2——样例未附复用/增量运行记录，不以此类推。仅当评测中有真实复用/增量执行时，才生成对应记录。

## 这是什么案例

- 被测对象：**retail-crm-service v1.0**（CRM 零售客服技能，行为 = τ²-bench retail 官方 policy）
- 测试集：τ²-bench retail 真实任务（GitHub `sierra-research/tau2-bench` → `data/tau2/domains/retail/`，policy.md + tasks.json）
- 用例：6 条真实用户场景（任务 0/2/3/5/10/12），按 3 大类 19 子类标注：功能类 正常路径 × 2 / 状态上下文 × 1 / 边界情况 × 1，对抗类 策略违规 × 2
- 执行方式：模拟运行（本环境无真实零售数据库），结果导向判定只看最终结果

## 怎么照着做（对执行 agent）

1. 先读 `three-piece.md`：理解三件套怎么从资料里来、黄金集怎么带来源、19 子类场景分类怎么勾选；本样例仅示范结构，不能替代真实执行记录。
2. 再读 `evaluation-report.md`：理解判定怎么落（每条不通过引用黄金集条款）、归因怎么分（技能行为 → 可回填 / 判定偏差 → 改口径）、汇总怎么算（无法判定单列）、结论怎么措辞（样本边界 + 样本量分级）。
3. 遇到新的被测技能时：按 S0 喂入对方资料 → 生成三件套草稿 → 给发起方确认 → 锁定 → 执行 → 判定 → 汇总 → 报告。

## 关键演示点（本样例刻意展示的）

- **结果导向**：判定只依据"最终输出 + 关键行为结果"，全程无轨迹分析；轨迹仅防守性（可否决、不可授分）。
- **缺证从严**：判定不了就无法判定，不猜通过。
- **阻断性生效**：crm-01/05/06 因规则边界阻断性失败 直接判整例不通过。
- **场景分类贯穿**：用例与黄金集共用 3 大类 19 子类；缺类 → 达标判定降级"覆盖不足、仅参考"。
- **归因拆分**：4 例不通过全部归因技能行为（可回填升级黄金集）；机制同时覆盖判定偏差（改口径、不回填）与无法归因（补证据）两类。
- **样本量分级措辞**：6 条 < 30 → 结论收紧"仅具参考意义、不具备统计显著性"。
- **黄金集可指回来源**：每条都落在 policy 条款或任务真实标注上。
- **诚实声明执行方式**：模拟运行在报告中明示，正式结论需真实环境回填。
