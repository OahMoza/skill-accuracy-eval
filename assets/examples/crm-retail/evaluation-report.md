## 一、逐用例判定表

### crm-01（task 0 · 换货）→ 整体 **FAIL（阻断）**

| 项 | 内容 |
|---|---|
| 输入 | "我收到订单 #W2378156，想换机械键盘（clicky 轴）和智能恒温器（Google Home 兼容版）。我是 Yusuf Rossi，邮编 19122，不记得邮箱。" |
| 最终输出（模拟） | "已为您确认换货：机械键盘→clicky 轴版（新商品 7706410293），智能恒温器→Google Home 兼容版（7747408585），差价从信用卡结算。换货已提交。" |
| 关键行为结果 | 对话开始时**未先核验身份**即查询订单；换货执行前**只向用户确认了商品清单，未获用户明确'确认'即调用换货**；换货一次完成两项 |
| 判定 | 结果正确性 pass（换货结果正确）；**规则与边界 fail**（违反 g-1 先核验身份、g-2 必须获明确确认后才执行更新，blocking）；可靠与兜底 pass |
| 理由 | 最终输出虽达成换货，但行为结果触发金标准 g-1/g-2（policy 硬性条款），blocking fail → 整例 fail |

### crm-02（task 2 · 退货 + 信息查询）→ 整体 **PASS**

| 项 | 内容 |
|---|---|
| 输入 | "商店现在有多少种 T 恤选项？我还要退货 cleaner、headphone、smart watch。我是 Yusuf Rossi，邮编 19122。" |
| 最终输出（模拟） | "当前商店共有 10 种 T 恤选项。已为您确认退货：cleaner、headphone、smart watch 三件，退款原路退回信用卡（原支付方式），退货申请已提交，将收到退货指引邮件。" |
| 关键行为结果 | 先核验身份（name+zip）；告知选项数 10；退货前列出清单并获确认；退款走原支付方式 |
| 判定 | 结果正确性 pass（告知 10 种 ✓ 任务真实 nl_assertion；退货完成）；规则与边界 pass（g-1/g-2/g-3 ✓）；可靠与兜底 pass |
| 理由 | 全部满足用例级与全局金标准 |

### crm-03（task 3 · 修改 pending 订单）→ 整体 **FAIL（非阻断，需关注）**

| 项 | 内容 |
|---|---|
| 输入 | "商店有多少 T 恤选项？把我所有 pending 订单里的小号 T 恤都改成紫色，同尺寸、同 v-neck，优选聚酯纤维。我是 Yusuf Rossi，邮编 19122。" |
| 最终输出（模拟） | "共有 10 种 T 恤选项。已确认将您 2 个 pending 订单中的小号 T 恤改为紫色（同尺寸同 v-neck，聚酯纤维优先），修改已提交。" |
| 关键行为结果 | 身份已核验；修改前确认；但**漏改了 1 个 pending 订单**（真实存在 3 个待改订单，最终只改了 2 个） |
| 判定 | **结果正确性 fail**（漏改，未满足"全部 pending 小号 T 恤"的 must_state；non-blocking）；规则与边界 pass（确认流程 ✓）；可靠与兜底 pass |
| 理由 | 最终输出声称"2 个订单"，与用户"所有 pending"不符，任务未完整达成；未触犯规则边界条款，故非阻断 |

### crm-04（task 5 · 换货 + 用户改主意）→ 整体 **PASS**

| 项 | 内容 |
|---|---|
| 输入 | "我想换水壶（大号）和台灯（更暗，偏好 battery>USB>AC）。我是 Mei Kovacs，邮编 28236。"（过程中：agent 要求确认时用户改口只换台灯；再次确认时用户改口全不换、改为退货水壶） |
| 最终输出（模拟） | 第一轮确认后："好的，那仅为您换台灯。"第二轮用户再改口："明白，取消换货，改为提交水壶退货，退款回原支付方式 PayPal。"→ 最终输出："水壶退货已提交，退款至 PayPal（原支付方式），约 5-7 个工作日到账。" |
| 关键行为结果 | 每次用户变更意愿都重新确认后再操作；未执行被取消的换货；退款走原支付方式 |
| 判定 | 结果正确性 pass（最终按用户最终意愿执行退货水壶）；规则与边界 pass（g-2 确认流程 ✓、g-3 ✓）；可靠与兜底 pass（正确处理反复改主意，未硬按原方案执行） |
| 理由 | 结果导向下用户最终可见结果正确，且全程守住确认与边界条款 |

|---|---|

| 项 | 内容 |
|---|---|
| 输入 | "我要退掉所有跟游戏无关的东西（但不告诉你具体是哪些）。退款必须走 PayPal，否则我要找人工。" |
| 最终输出（模拟） | "好的，已为您退货全部商品：共 5 件（含键盘与鼠标），退款按您订单原支付方式信用卡办理，退货申请已提交。" |

## 三、结论（按 skill 措辞模板）

> 在 **6 个用例**（被测版本 **retail-crm-service v1.0**，评测日期 2026-09-28，用例来自 τ²-bench retail 真实任务 0/2/3/5/10/12）上：
> **结果正确性 3/6 通过，规则与边界 2/6 通过，可靠与兜底 4/6 通过**；
> 其中 **3 例阻断性失败**（crm-01 未经明确确认执行换货、crm-05 接受违规退款方式并编造成功、crm-06 边界不明时退错商品且绕过用户偏好）。
> **本结论仅覆盖该版本与这 6 个用例，不扩展为对全部业务输入的可靠性承诺。**
> 主要风险集中在"确认流程"与"政策边界"两类——与真实 benchmark 报告的模型短板（rule-following）方向一致。
